# Request DSL wire contract

The table below lists every accept/reject rule of the request parser under `crates/khive-request/src/parser/`, one row per rule, with the obligation it places on any client that renders DSL text. Each row quotes the parser line it derives from, and `python/tests/test_dsl_contract.py` asserts every quoted line still exists in the cited file, so a parser change that removes or rewrites a rule fails the Python suite until the table is updated.

**Citation:** that audit proves presence and count — the quoted text exists in the named file, at the declared occurrence count (1, unless the row marks `{shared=N}`). It does not prove the quote sits on the deciding branch: a citation whose text happens to recur unchanged elsewhere in the file would still pass with existence alone. Naming the actual decision a row claims — not just a line that contains matching text — is a reading obligation on the row's author, not something this audit enforces.

**Reasons:** error reason strings — the `expected` text, byte positions, and message wording — are not part of the wire contract. A client may depend only on accept/reject and, where a row names it, on the error variant class; the offline fake in `python/tests/_dsl_fake.py` pins exactly that and nothing about wording.

## Not covered

- `DslError::WriteKeyConflict` is declared in `crates/khive-request/src/types.rs`, but no parser branch constructs it; it belongs to later parallel-write conflict handling and is therefore not a parser rule or an entry in the parser-error table.
- Exact JSON lexical edge behavior and dependency-specific diagnostic wording are delegated by the parser to serde_json in `crates/khive-request/src/parser/parser_impl.rs`; the table records the parser's delegation contract and representative inputs, not an independent reimplementation of that dependency.
- `parse_typed_json_batch` is already-decoded input: its source-byte bound is explicitly the caller's responsibility, as documented in `crates/khive-request/src/parser/dispatch.rs`; no transport decoder or caller-side byte limit can be derived from the parser itself.
