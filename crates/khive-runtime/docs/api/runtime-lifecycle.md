# Runtime lifetime and store release

Source snapshot: `db065e0eb863e6ee1354c2f1887f8100462e3868`.
This inventory describes current ownership; it does not promise that dropping a
runtime settles its storage. An embedding host that evicts tenant runtimes needs
both task completion and closure of the tenant's file handles before eviction is
complete.

`KhiveRuntime` is cloneable and has no custom destructor. A last _host_ handle is
not necessarily the last owner: registries, stores, in-flight requests, background
work, and process caches can retain a backend. User-provided packs, embedders,
blob stores, hooks, and fusion executors are extension boundaries; their private
resources cannot be discovered or joined through the current runtime interface.

## Existing explicit settle sequence

`kkernel/src/exec/run.rs:570` documents the current exec sequence:

1. Drain the registry audit batch.
2. Take every pool's standalone writer join.
3. Drop the server and all local storage references.
4. Await those joins, bounded at five seconds each.

It logs and swallows failures, so it is advisory rather than a successful-return
close guarantee. It also does not evict events process caches or expose a
per-tenant boundary for the conditional resources above. A shared close helper
must preserve this existing exec behavior and distinguish tenant-owned resources
from process-owned services before claiming that it releases every resource.

## Baseline measurement

The first measurement is intentionally bounded to a private file-backed runtime,
KG registry, entity and note writes, and a real audited dispatch. It excludes
embeddings, events splitting, ANN, blob storage and serve loops. It is evidence
for this configuration only; the optional rows above need their own fixtures.

On a single-thread Tokio executor, snapshot the writer join immediately after
dropping all runtime, registry and store handles, without yielding. The writer
cannot consume the closed channel until the executor polls it again. Expected
base result: the task-completion arm is **red**. A process handle census should
also still find the standalone connection, making the file-release arm **red**.
A later awaited normal join provides cleanup and an independent settled snapshot;
that later snapshot must not replace the immediate observation.

Reopening SQLite and committing a write is recorded separately. SQLite permits
multiple writable connections, so this may succeed while the first writer still
exists. It cannot, by itself, prove single-writer ownership or serve as a reliable
must-fail control for a skipped writer join. The original writer's completion
witness and file census supply the missing evidence.

The file-release assertion is one platform-independent condition over a
process-local census. The initial census adapters cover Linux (`/proc/self/fd`)
and macOS (libproc descriptor inventory plus `F_GETPATH`). Other platforms return
an explicit unsupported error, not an empty census. This is **not yet Windows
coverage**. A live file and directory canary must be detected before accepting
an empty result. Snapshot races, external aliases, custom provider resources and
memory mappings without live file descriptors remain separate from this
bounded fixture; a path deletion or successful rename is never used as release
proof.

No close implementation is selected from source inspection alone. The immediate
and settled observations must be collected before changing shutdown behavior.
