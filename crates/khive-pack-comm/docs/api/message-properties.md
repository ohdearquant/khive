# Message properties v1

`message` notes written by the comm pack carry their machine-readable contract in the note's
`properties` JSON object. This is a stable external-reader surface: dashboards and adapters may
read these fields directly, but must branch on `comm_schema_version` before interpreting them.

## Version negotiation

Every message written by `comm.send`, `comm.reply`, or `comm.ingest` carries the integer
`comm_schema_version`. The current value is `1`.

- A missing marker identifies a pre-versioning message. It must not be assumed to use v1.
- An unknown value must be handled explicitly rather than silently interpreted as v1.
- Readers must ignore unknown properties. Transport adapters may add metadata outside the stable
  table below.
- A change to the presence, type, or meaning of a stable field requires a version bump. Adding a
  field to the stable table also requires a bump.

There is no data migration or backfill. Existing messages retain their original properties.

## Stable fields

| Field                 | JSON type      | Presence                             | v1 invariant                                                                                                                             |
| --------------------- | -------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `comm_schema_version` | integer        | Always on new comm-authored messages | Exactly `1`.                                                                                                                             |
| `direction`           | string         | Always                               | `"outbound"` or `"inbound"`.                                                                                                             |
| `read`                | boolean        | Always                               | Initially `false`. Only an inbound recipient action changes it to `true`.                                                                |
| `from_actor`          | string         | Always                               | Sender actor label; the unattributed single-actor fallback is `"local"`. For `comm.ingest`, this is the transport sender.                |
| `to_actor`            | string         | Always                               | Destination actor label. `comm.ingest` resolves it from correlation, `default_inbound_actor`, or the transport recipient, in that order. |
| `from`                | string         | Always                               | Legacy addressing value. `comm.send`/`comm.reply` retain the caller storage namespace; `comm.ingest` retains the transport sender.       |
| `to`                  | string         | Always                               | Legacy addressing value. `comm.send`/`comm.reply` retain the caller storage namespace; `comm.ingest` retains the transport recipient.    |
| `thread_id`           | string         | Always                               | Full hyphenated canonical-root UUID; valid alternate UUID spellings are normalized before storage.                                       |
| `subject`             | string or null | Optional                             | Missing and JSON `null` both mean no subject.                                                                                            |
| `sent_at`             | string         | Always                               | RFC 3339 timestamp generated by the comm pack, or a validated adapter timestamp normalized to UTC before storage.                        |
| `outbound_ref`        | string         | Paired inbound delivery copy only    | Full UUID of its outbound twin. Directly ingested inbound messages have no outbound twin and omit this field.                            |
| `sent_by_process`     | string         | Optional on paired delivery copies   | Exact `KHIVE_PROCESS_REF` value observed for the `comm.send` or `comm.reply`; see below.                                                 |

For a root dual-write, the canonical `thread_id` is the outbound copy's UUID.

The schema version describes the stored `properties` object. It does not replace a note's own
top-level `id`, `namespace`, `content`, `created_at`, or `updated_at` fields.

## Optional process provenance

When `KHIVE_PROCESS_REF` is present at `comm.send` or `comm.reply` dispatch time, the originating
request process reads it once and carries the exact Unicode string through the daemon request
context when necessary. The comm pack copies it to `sent_by_process` on both the outbound and
inbound delivery copies. The value is opaque: khive does not parse, normalize, authorize, route,
filter, or deduplicate by it. A spawner may use a run id, job id, process id, or another private
vocabulary. A shared warm daemon never substitutes its own environment for an absent caller value.

When the variable is absent, `sent_by_process` is omitted rather than written as `null`; send and
reply response shapes, routing, gate checks, and visibility are unchanged. A non-Unicode process
environment value cannot be represented as JSON and is omitted with a warning. `comm.ingest` does
not stamp this field because the process running an adapter is not the author of the externally
received message.

Process provenance is not an identity or authority signal. `from_actor` remains the actor identity
used by routing and authorization.

## Extension fields

V1 messages may carry additional properties such as `tags`, `external_id`, `wire_message_id`,
`wire_references`, `channel_kind`, `in_reply_to_message_id`, `references_chain`, and
adapter-supplied metadata. These do not weaken the stable-field invariants. Stable field names are
reserved during ingest even when an optional field is absent, so adapter metadata cannot override
or fabricate one.
